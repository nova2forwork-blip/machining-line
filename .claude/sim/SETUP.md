# กติกากลางของทีมทดสอบจำลอง (อ่านก่อนเริ่มทุกครั้ง)

ทุกคนในทีมเป็น "ผู้ใช้จำลอง" ที่ลงข้อมูลและแก้ไขข้อมูลจริงในแอป Artclad Production
เพื่อหาบั๊ก ความไม่สะดวก และข้อมูลที่ไม่ตรงกัน **หน้าที่คือทดสอบและรายงาน ไม่ใช่แก้โค้ด**

## 1. ความปลอดภัย — ห้ามข้าม

1. ทำงานบน branch `local-test` เท่านั้น ห้าม checkout / merge / push `main`
2. **ก่อนเขียนข้อมูลใดๆ ต้องเช็กว่าแอปต่อ Supabase ในเครื่อง**
   - เปิด `.env.local` ดู `VITE_SUPABASE_URL` ต้องเป็น `same-origin`, `http://127.0.0.1:…` หรือ `http://localhost:…`
   - ถ้าเป็น `https://….supabase.co` (ตัวจริงบนเว็บ) → **หยุดทันที** แจ้งผู้ใช้ ห้ามทดสอบต่อ
   - เช็กว่า Supabase ในเครื่องเปิดอยู่: `npx supabase status` (หรือ `supabase status`)
3. ห้ามแก้ไฟล์ใน `src/`, `supabase-schema.sql`, `migration-*.sql` ห้าม commit อะไรทั้งนั้น
4. ห้าม commit / แชร์ `roles.sql`, `schema.sql`, `data.sql`, `.env*`, `package-lock.json`
5. รหัสผ่านที่ผู้ใช้ให้มา ห้ามเขียนลงไฟล์ใดๆ ใน repo (ใช้เป็นตัวแปร environment ตอนรันเท่านั้น)
6. repo เป็น public — ภาพหน้าจอและรายงานเก็บใน `.sim/` เท่านั้น (ถูก gitignore ไว้แล้ว)

## 2. แยกข้อมูลของแต่ละคน ไม่ให้ชนกัน

- สร้างโปรเจกต์ทดสอบของตัวเอง ชื่อขึ้นต้นด้วยรหัสของตัวเอง เช่น `SIM1-…`, `SIM2-…`
- ห้ามแก้ / ลบโปรเจกต์ที่ไม่ได้ขึ้นต้นด้วย `SIM` (เป็นข้อมูลจริงที่คัดลอกมา) — **อ่านดูได้ แต่ห้ามบันทึก**
  ยกเว้นผู้ใช้สั่งเองว่าให้ทดสอบกับโปรเจกต์นั้น
- ไฟล์ PDF / Excel ตัวอย่าง: ถามผู้ใช้ว่าอยู่โฟลเดอร์ไหน ถ้าไม่มี ให้ดึงจากโปรเจกต์จริงในเครื่อง
  (Storage ของ Supabase ในเครื่อง) มาใช้กับโปรเจกต์ SIM ของตัวเอง

## 3. เครื่องมือ

- แอป: `npm run dev` (พอร์ต 5173) — ถ้ามีคนเปิดไว้แล้ว ใช้ตัวเดิม ไม่ต้องเปิดซ้ำ
- เบราว์เซอร์อัตโนมัติ: Playwright ติดตั้งใน `.sim/` (ไม่แตะ package.json ของโปรเจกต์)
  ```
  mkdir -p .sim && cd .sim && npm init -y && npm i playwright pg && npx playwright install chromium
  ```
  สคริปต์ทดสอบเขียนไว้ที่ `.sim/<รหัส>/*.mjs`
- ฐานข้อมูลในเครื่อง (ใช้ตรวจว่าที่บันทึกตรงกับหน้าจอ):
  `postgresql://postgres:postgres@127.0.0.1:54322/postgres` (ค่าเริ่มต้นของ supabase start —
  ถ้าไม่ตรง ดูจาก `npx supabase status`) ใช้ `psql` หรือ node + `pg` ใน `.sim/`
- ล็อกอิน: แอปใช้ **รหัสพนักงาน + รหัสผ่าน** ขอจากผู้ใช้ผ่านหัวหน้าทีม
  (ต้องมีอย่างน้อย admin 1 บัญชี; ถ้าต้องการ office / operator ให้ admin สร้างในหน้า ตั้งค่า → พนักงาน
  ตั้งชื่อขึ้นต้น `SIM`) รับรหัสผ่านทาง env เช่น `SIM_CODE`, `SIM_PASS`
- ขนาดจอ: 1440×900 (คอมออฟฟิศ) เป็นหลัก · 820×1180 (iPad) เฉพาะ SIM4 / เมื่อไม่ได้จำกัดขอบเขต office

## 4. วิธีทดสอบ

- เล่นเป็นคนจริงตามบทบาทของตัวเอง: กรอกช้า/เร็ว พิมพ์ผิดแล้วแก้ กด Esc กดนอกกรอบ รีเฟรชกลางทาง
- **ทุกครั้งที่บันทึก** ให้ตรวจ 3 ชั้น: (1) หน้าจอแสดงถูกไหม (2) รีเฟรชแล้วยังอยู่ไหม
  (3) ใน database ตรงกับหน้าจอไหม
- ทดสอบ Ctrl+Z หลังแก้ ทั้งก่อนและหลังบันทึก
- ถ่ายภาพหน้าจอเมื่อเจอปัญหา เก็บที่ `.sim/<รหัส>/shots/`
- ดู console ของเบราว์เซอร์ทุกหน้า — error สีแดงนับเป็นปัญหา

## 5. รูปแบบรายงาน (ส่งกลับให้หัวหน้าทีม)

เขียนเป็นภาษาไทย บันทึกที่ `.sim/<รหัส>/report.md` และส่งเนื้อหาเดียวกันกลับมา:

```
# <รหัส> <บทบาท> — สรุป
ทดสอบแล้ว: <รายการสิ่งที่ลอง สั้นๆ>
ไม่ได้ทดสอบ: <สิ่งที่ทำไม่ได้ + เหตุผล>

## ปัญหา (เรียงจากร้ายแรงสุด)
### [ร้ายแรง|สำคัญ|เล็กน้อย|ข้อเสนอ] <หัวข้อสั้น>
- หน้า: <เมนู > แท็บ>
- ขั้นตอน: 1. … 2. … 3. …
- ที่ควรเป็น: …
- ที่เกิดจริง: …
- หลักฐาน: <ภาพ / ค่าใน DB / ข้อความ error>
- เกิดซ้ำได้: ทุกครั้ง | บางครั้ง
```

ระดับ: **ร้ายแรง** = ข้อมูลผิด/หาย/บันทึกผิดที่ · **สำคัญ** = ทำงานต่อไม่ได้หรือต้องอ้อม ·
**เล็กน้อย** = หน้าตา/ข้อความ · **ข้อเสนอ** = ใช้ได้แต่ไม่สะดวก

ห้ามรายงานสิ่งที่ไม่ได้ลองจริง ถ้าไม่แน่ใจให้เขียนว่า "ไม่แน่ใจ" พร้อมเหตุผล
